# 4. Share the transition table as moves.json

Date: 2026-11-21

## Status

Accepted

## Context

The status shortcut (formerly sv-status.md) offers a menu of moves (MOVES), while state_tool.py's user_transition classifies a user's change. Both must agree, and the menu's guards (held_only, unheld, done_proposed, not_proposed) depend on the note body format, which has changed before (0.65.3 moved the meta line).

Alternatives considered:

- Generate the table from Python. Rejected: labels and guards cannot be derived from the classifier.
- Keep it in JS only. Rejected: no cross-check between the languages.

## Decision

src/moves.json holds the transition table. TypeScript imports it, and pytest reads it and checks every move against user_transition. The guard fixtures (skill/tests/fixtures/notes-gen/*.md) are generated by pytest from state_tool's own note writing; the expected flags in expected.json are written by hand in the generation test. vitest checks the TypeScript guards against the same files, and CI checks that regenerating the fixtures produces no diff.

## Consequences

- The table lives in one place, and a note format change in Python shows up as a fixture diff.
- The guards exist only in TypeScript; their agreement with the format is checked through the fixtures.
